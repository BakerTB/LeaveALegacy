Alpaca API Integration

The bot uses alpaca-py — Alpaca's official Python SDK — to connect three independent clients that handle different parts of the pipeline.

Client initialization
trading_client = TradingClient(API_KEY, API_SECRET, paper=True)
stock_data_client = StockHistoricalDataClient(API_KEY, API_SECRET)
option_data_client = OptionHistoricalDataClient(API_KEY, API_SECRET)
Client 1
TradingClient
Places and manages orders, reads open positions, queries account P&L. Handles the full order lifecycle from entry to exit. Supports paper and live modes via a single flag.
Client 2
StockHistoricalDataClient
Fetches OHLCV bars and caches them in a rolling window that refreshes each candle — so the bot always has a fresh, trimmed price history without redundant API calls.
Client 3
OptionHistoricalDataClient
Queries live option contract data — fetches the current bid/ask/mid premium for a specific contract symbol to estimate real fill price before committing to an order.
The Execution Pipeline
→Market hours check: The bot queries whether the market is currently open before doing anything. If it's outside the trading window, it calculates the exact seconds until the next window and sleeps precisely — no wasted API calls.
→Contract discovery: Uses GetOptionContractsRequest to find the right option contract for a given underlying symbol, strike price, and expiry. Returns the actual contract object used for ordering.
→Premium estimation: Before placing an order, the bot fetches the live contract premium via the options data client. Falls back through bid, ask, and mid price to always get a usable estimate — then sizes the order to a fixed notional budget.
→Order placement: Uses MarketOrderRequest with OptionLegRequest to submit the trade. Quantity is computed from the notional budget divided by estimated premium — so position size scales automatically with price.
→Exit monitoring: After entry, the bot polls the open position on every candle, checking live P&L percentage. If a profit target is hit, it sells immediately via MarketOrderRequest on the other side.
→Daily P&L circuit breaker: Queries account-level daily P&L each cycle. If the daily loss limit is exceeded, the bot blocks all new entries for the rest of the session — protecting the account from runaway losses.
→Timezone-aware logging: A custom ChicagoFormatter timestamps every log line in Chicago (CT) time — matching market hours — so the logs are always immediately interpretable without converting timezones.
Triple Indicator Research — The Exploration Phase
Note: The triple-indicator approach below was an early exploration and backtesting framework — not the strategy running in the actual live bot. The live strategy is proprietary and not documented here.

During development, I explored requiring confluence from three independent indicators before triggering any trade — the idea being that a signal confirmed by three separate systems produces far fewer false positives than any single indicator alone.

RSI — Relative Strength Index
Momentum oscillator measuring speed and magnitude of recent price changes. Signals overbought (>70) and oversold (<30) conditions. Implemented from scratch.
Fair Value Gaps (FVG)
Price inefficiency zones created when a candle moves so fast it leaves a gap. The market often returns to fill these gaps — the research explored entering when price re-enters the gap zone.
S&R Bands
Dynamic bands at prior session highs, lows, and closes. Price behavior near these levels has high predictive value. Also published as a custom indicator on TradingView.
